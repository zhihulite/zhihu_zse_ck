## 2. 订正一条旧结论（有证据）

`GO_RESTORE_STATUS.md §14.4②` 把 `_o0OOOo` 等 8 个方法记为「循环左移/循环右移 = 密码轮函数」。
**实测否证**：全 104 个 `$bound` 里 `(x << k) | (x >> (32-k))` 形式的**真循环移位出现 0 次**。
实际位移量只有 `<<1..<<16` 与 `>>1..>>7`，且**没有互补回环** ⇒ 是**位字段提取**，不是循环移位。

例（`_o0OOOo` 原文）：
```js
function __main__0oOoOO___o0OOOo$bound(p0) {
  l2 = M32[p0 + 20];            // pc
  l1 = l2 + 1; M32[p0 + 20] = l1;
  l3 = M32[p0 + 312];           // program len（10565）
  if (l1 >= l3) break $B0;      // 越界检查
  l4 = M32[p0 + 308];           // program ptr
  l5 = M32[l4 + (l1 << 2)];     // 内联字 #1 = prog[pc+1]
  l1 = l2 + 2; M32[p0 + 20] = l1;
  if (l1 >= l3) break $B0;
  l1 = M32[l4 + (l1 << 2)];     // 内联字 #2 = prog[pc+2]
  M32[p0 + 20] = l2 + 3;
  __main__0oOoOO___00oooO(p0, (l1 | (l5 << 8)));   // p1 = 两字按位拼合
  return;
}
```

## 4. 仍未闭环

- `p1`（35 臂编号）与 `prog[pc]`（0..103 表索引）的**精确对应**仍需按帧追踪：
  `_00oooO` 是递归子帧，入口 pc 混帧；且 `p1` 由**内联操作数**参与计算 ⇒ 不是静态一 op 一 p1。
- 运行时分派表 dump 显示 104 项**共用同一 funcptr（314292）**、第二字段是 `104-op`（1..104 的整数），
  与「104 个不同 handler」的直觉不符 —— 该字段语义待定。
